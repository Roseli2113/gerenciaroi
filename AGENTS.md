# Architecture rules
- Apply investment tax via `withInvestmentTax` only to the returned reporting rows of `useMetaCampaigns`; keep state/cache raw and budgets/write APIs unchanged, so all reporting consumers include tax once without compounding it. The rate comes from `investment_tax_settings` per user (default 0.12) via `useInvestmentTaxRate`.
- Sale alerts come from the server push; the realtime toast runs only in browsers without a push subscription, both build text via `supabase/functions/_shared/saleNotificationMessage.ts`, share one owner-scoped sale claim, and only MainLayout enables listeners; this keeps one alert per sale with identical, preference-respecting content.
- Keep user-specific fallback attribution in `sales_attribution_settings` and aggregate it separately in `useSalesAttribution`; this applies to historical and future sales without mutating source UTMs or Meta conversion events.
- Add manual fallback metrics only at campaign/account reporting level after hierarchy rollup; this avoids inventing attribution to ad sets or ads.
- Test attribution eligibility with `bun test src/lib/trafficAttribution.test.ts src/lib/manualSaleAttribution.test.ts`; business rules must remain independently verifiable.
- Persist per-sale hierarchy overrides in `manual_sale_attributions`, scoped to the sale owner; replace automatic attribution and add separate manual maps after rollups only at explicitly selected campaign, ad-set and ad levels, without changing sales, UTMs or Meta events or double-counting parent totals.
- Always replace Meta financial metrics with webhook attribution, including zero results, through `campaignFinancials`; pixel conversions must not appear as actual sales.
- Bound Meta reporting requests with client timeouts, fail fast on Meta account throttles (no long server retries), and keep last successful rows per user/accounts/period in localStorage; retries burn quota and empty tables mislead users.- Save browser push subscriptions only through `claim_push_subscription` (one owner per endpoint, moved to the signed-in account); a browser shared by several accounts would otherwise get one alert per account for the same sale.
- Keep per-user billing overrides (custom price, due date, custom checkout link) in `subscription_billing`, admin-writable only, and compute due days/price via `src/lib/billing.ts`; the plan stays independent of what the user pays.
- Admin "view as user" swaps `useAuth().user` to the target (real account in `realUser`), relies on admin-only SELECT policies, and `src/lib/viewAs.ts` blocks every write/RPC and non-`get-*` function call; signing in as another user is not allowed by the platform.
- Render money through `formatBRL` / `formatBRLShort` in `src/lib/formatBRL.ts` instead of per-component `toFixed`; the hand-built grouping keeps the thousands dot and decimal comma identical in every runtime and keeps the rule testable in `src/lib/formatBRL.test.ts`.
